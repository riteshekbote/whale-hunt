## Why nothing is VALID

The program rules mandate `passive_first: true` ("GET/HEAD reads first; client-side scope: static analysis + repro-first"). Every surviving hypothesis is a **client-side browser-binary bug** whose verification requires either (a) acquiring the Whale binary (all in-sandbox download channels are Cloudflare-403 / DNS-blocked — confirmed dead), (b) `objdump`/`strings`/`.rodata` disassembly of a held binary, or (c) a runtime authenticated session with crafted inputs. **None** of these are provable with passive GET/HEAD alone, so **Q4 fails for every lead**. The reposcan layer that *would* produce URL-level probes returned `0 files / 0 hits` across all 40+ runs — there is no live-endpoint finding to validate.

Additionally, Q7 (reasonable triager acceptance) fails for all leads because there is **zero evidence of an actual vulnerability** — only evidence that a surface exists and has historically had bugs.
