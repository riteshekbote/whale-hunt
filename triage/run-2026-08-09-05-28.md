## Critical findings about the pipeline itself

This is the most important part of the triage:

1. **All 5 models are hypothesis-generating, not evidence-generating.** Every `verify_steps` is `HUMAN_ONLY` or `AUTH_HELPED` — none satisfy `passive_first: true` from scope.yml. The bot is optimized to *produce leads*, not *prove them*.

2. **The probe engine is non-functional.** `probe-results.md` contains only `ERR` (DNS) and uptodown 200/404/400. Zero Whale assets were obtained. No binary, no version, no KDF constant, no diff.

3. **Models are not deduplicating.** The same 3 hypotheses appear identically across all 5 lead files, inflating apparent confidence via repetition. HYP-1 is not "confirmed by 5 models" — it's one hypothesis copied 5 times.

4. **"0 CVEs published in 2026" is treated as a vulnerability signal.** It isn't. It's an absence of evidence, not evidence of a bug.

5. **Disclosure channel is TBD.** `scope.yml` says `disclosure_policy: TBD`. No valid bug can be reported until this is populated.

---

## Recommendation

**No leads pass the gate this round.** The pipeline needs:
- A working binary-acquisition path (or acceptance that binary-dependent hypotheses are unprovable)
- A triager that enforces Q4 *before* escalating — reject anything that isn't GET/HEAD-provable
- A dedup layer so 5× copies of the same hypothesis don't masquerade as independent corroboration
- A populated disclosure policy before any VALID can be actioned
